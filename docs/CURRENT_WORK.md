  1. **Pure Domain Economy & Level Curve**:
     - Attempt XP is 6 for Correct, 1 for Incorrect; Defeat bonus is 1 XP/attack for Normal, 2 XP/attack for Boss; Boss milestone bonus is 10 XP.
     - Level curve: $SP = \text{Level} - 1$; per-level delta $\Delta\text{XP}(\text{level}) = \lceil 80 + 24 \cdot (\text{level}-1)^{0.75} \rceil$ ($\text{level} \le 100$) and $\lceil 834 + 160 \cdot \log_2(\text{level} / 100) \rceil$ ($\text{level} > 100$); cumulative threshold $\text{Threshold}(1) = 0$ and $\text{Threshold}(L) = \sum_{k=1}^{L-1} \Delta\text{XP}(k)$ ($L \ge 2$) derived from deterministic integer/ceiling mathematical functions without RNG.
  2. **Attack Upgrade Policy**:
     - Base damage is 1; $D(\text{rank}) = 1 + \text{rank}$; cost of purchasing the next rank $C(\text{nextRank}) = 1 + \lfloor \log_2(\text{nextRank}) \rfloor$ with `nextRank = currentRank + 1` (1 SP for rank 1, 2 SP for ranks 2–3, 3 SP for ranks 4–7, 4 SP for ranks 8–15).
  3. **SQLite Gameplay Store Schema V4**:
     - Table `gameplay_progression`: persists `cumulative_xp`, `player_level`, `earned_sp`, `spent_sp`, `available_sp`, `attack_rank`, `economy_version`. Enforces `CHECK (earned_sp = spent_sp + available_sp)`.
     - Table `gameplay_run_state`: persists `opponent_executed_attacks` and `opponent_encounter_provenance`.
     - Table `gameplay_pending_intent`: persists `effective_attack_damage` with `CHECK (effective_attack_damage >= 1)`.
     - Table `gameplay_receipt_ledger`: persists `awarded_xp`, `player_level_after`, `cumulative_xp_after`, `next_opponent_executed_attacks`, `executed_attacks_on_defeated_opponent`, and provenance metadata.
  4. **Atomic Transactions & SP Conservation**:
     - Purchases and XP settlements execute within atomic SQLite transactions, validating reset epoch, expected rank, and available SP.
  5. **Question-Bound Attack Damage Semantics**:
     - Damage is bound at question presentation / dispatch via `CombatCoordinator.GetOrBindEffectiveAttackDamageAsync(Session.FactInstanceRevision)` and persisted in `gameplay_pending_intent`.
     - `TrainingSession` owns arithmetic practice and `FactInstanceRevision`; `CyberDefenseCombatCoordinator` owns the authoritative question-bound attack damage.
     - Mid-turn upgrade purchases affect strictly future questions; in-flight questions retain their bound damage.
  6. **Pause-Safe Upgrade Terminal Lifecycle**:
     - Opening Upgrade Terminal synchronously pauses item timing before any async await (`Session.PauseItemTiming()`).
     - Closing the terminal resumes timing only when returning to active running practice (`Session.ResumeItemTiming()`).
     - Current question fact, `FactInstanceRevision`, partial answer buffer, and keypad state are preserved without mutation or penalty.
